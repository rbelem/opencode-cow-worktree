## Observations (non-defects)

1. `.3` logs the plugin load as `msg="loading plugin" id=<directory path>`
   — the plugin directory path, not the `opencode-cow-worktree` id. Binary-
   side log-format change; activation state via `GET /api/plugin` is
   unaffected.
2. W2's harness overrode `OPENCODE_CONFIG_DIR` but not `HOME`, so its server
   resolved the global config from the live user seam
   (`~/.config/opencode/plugins/opencode-cow-worktree`) instead of an
   isolated copy. Same plugin source (symlink to this repo at `dcc8ce1`), so
   the W2 verdicts stand; W4 independently proved the isolated-load path on
   `.3`.
3. A pre-existing, unrelated `opencode2 serve --service` process (started
   before the swarm, port 49374) was left untouched.

## What this run did not prove

Same limits as `run-2026-09-12.md`: no real multi-agent LLM fan-out (no
provider credentials; filesystem and tool behavior only), the interactive TUI
surface (badge rendering) was not exercised headless, and the v2 transcript
exposes tool state as text, so the raw structured `output` object was
verified via the declared schema plus the runtime text.
